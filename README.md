# LAB01 — Cisco network automation в EVE-NG

Учебная сетевая лаборатория OTUS. **Источник правды — две плоские CSV-таблицы**
(`devices.csv`, `links.csv`). Из них генерятся переменные, рендерится один Jinja-шаблон,
Ansible применяет конфиги на все устройства по SSH.

Подробная топология и адресный план — [`TOPOLOGY.md`](TOPOLOGY.md).
Концепции инструментов (telnet, expect, SSH, Ansible) — [`WORKFLOW.md`](WORKFLOW.md).

## Зачем Ansible

Меняешь строку в `devices.csv` или `links.csv` → `python csv2yaml.py` перегенерирует
переменные в `host_vars/` → `ansible-playbook apply.yml --check --diff` показывает,
что будет изменено на каждом устройстве → одобрил → applied на всех 18 за один заход.

Один источник правды, одна точка применения. Любое изменение видно через `git diff`,
ничего не правится руками на устройстве. Если что-то сломалось — `git revert` и
применил обратно.

Под капотом: `cisco.ios.ios_config` модуль ходит SSH'ом, сравнивает running-config
с тем что нагенерил шаблон, и поинтефарово приводит к нужному состоянию.

## Адресный план

| Назначение | Формула | Пример |
|---|---|---|
| Лупбэк роутера | `10.{site}.255.{id}/32` | R12 → `10.1.255.12` |
| In-band mgmt | `10.{site}.250.{id}/24` | R12 → `10.1.250.12` |
| OOB mgmt | `192.168.100.{id}/24` | R12 → `192.168.100.12` |
| Intra-AS P2P | `10.{site}.254.x/31` | `10.1.254.0/31`, `10.1.254.2/31`, ... |
| Inter-AS P2P | `172.16.0.x/31` | `172.16.0.0/31`, `172.16.0.2/31`, ... |

`site` — индекс AS (Moscow=1, SPB=2, Lamas=3, ...). `id` — числовой суффикс имени.

## Архитектурные решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где живёт Ansible | На EVE-хосте | Уже в L2 со всеми `pnetX`-бриджами лабы. WSL отключён под VMware Player. |
| Mgmt-сеть для автоматизации | OOB `192.168.100.0/24` | In-band per-site VLAN требует рабочей L3-связности — а мы её только собираемся настраивать. Курица-яйцо. |
| Mgmt-интерфейс | `Ethernet1/3` на всех | IOL: интерфейсы группами по 4. Вторая portgroup → mgmt на крайнем порту, не "съезжает" при добавлении лабораторных линков. |
| Соединение mgmt с EVE-хостом | `Cloud1` (`pnet1`) | `Cloud0` = домашняя сеть (грязно). `Cloud1` = внутренний бридж EVE; EVE-хост его видит, наружу не торчит. |
| Telnet vs SSH | SSH (telnet — fallback) | `ansible.netcommon.network_cli` работает только по SSH. |
| Версия Ansible | 6.x (core 2.13), pip | apt 2.9 — EOL. core 2.14+ требует Python 3.9+, у EVE 3.8. |
| `paramiko<3.0` | Обязательно | 3.x отрезает `ssh-rsa`, поддерживаемый IOL 15.4. |
| SSH-опции к IOL | `KexAlgorithms=+diffie-hellman-group14-sha1`, `HostKeyAlgorithms=+ssh-rsa` | IOL 15.4 знает только устаревший KEX/HostKey. Опции в `ansible_ssh_common_args` глобально. |

## Что дальше

1. **Apply P2P-конфигов** (`apply.yml --limit routers --check --diff` → если ок → без `--check`).
   Verify через ping между смежными лупбэками.
2. **Bootstrap свитчей** (SW2..SW29) — та же процедура, что и роутеров, шаблон уже умеет
   рендерить switch-вариант (SVI Vlan1 + `ip default-gateway`).
3. **Static routes** для cross-site reachability.
4. **`ios_config` → declarative модули** (`ios_user`, `ios_interfaces`, `ios_l3_interfaces`)
   для настоящей идемпотентности.
5. **OSPF / BGP**, когда курс дойдёт.

## Лаба vs прод

- Пароли в `group_vars/all.yml` — открыто. В проде — `ansible-vault` или secret store.
- `host_key_checking = False` — для лабы ок. В проде — проверять fingerprints.
- Устаревшие KEX/HostKey-опции нужны только для IOL 15.4. На современном оборудовании не используются.
- `transport input ssh telnet` — telnet как fallback. В проде отключают.
